### НОД

Обе функции принимают два неотрицательных целых числа типа `int`.
Отрицательные значения вызывают `ValueError`, другой тип (включая `bool`)
вызывает `TypeError`. Приняты соглашения `gcd(a, 0) = a` и `gcd(0, 0) = 0`.

Используется равенство `gcd(a, b) = gcd(b, a % b)` при `b != 0`.
В итеративном варианте пара обновляется в цикле, в рекурсивном происходит
вызов с новой парой. Базовый случай рекурсии: второй аргумент равен нулю.

Глубина рекурсии ограничена Python. Текущее ограничение можно узнать через
`sys.getrecursionlimit()`; конкретное значение зависит от окружения.
При слишком большой глубине возникает `RecursionError`. Лимит относится ко
всему стеку вызовов, поэтому число доступных вызовов функции может быть меньше
этого значения. Пакет лимит не меняет. Для огромных чисел предпочтителен
итеративный вариант. Соседние числа Фибоначчи дают длинную цепочку алгоритма
Евклида и могут довести рекурсивный вариант до ограничения.

### Сортировки

Обе функции принимают `list`, содержащий только значения точного типа `int`
(без `bool`, вещественных чисел и строк). Неверный контейнер или элемент
вызывает `TypeError`. Поддерживаются отрицательные числа, дубликаты, пустой
список и один элемент.

Функции всегда возвращают новый список по возрастанию. Исходный список не
меняется, в том числе при ошибке проверки типов. `sorted` и `list.sort`
в реализациях сортировок не используются. `sorted` применяется для подготовки
тестовых наборов и как эталон в тестах и benchmark вне таймера.

Сортировка вставками по очереди вставляет очередной элемент в уже
отсортированный префикс. Сортировка слиянием делит список на две части,
сортирует их рекурсивно и объединяет за один линейный проход.

### Стек

`Stack` хранит произвольные объекты по правилу LIFO:

- `push(value)` добавляет элемент на вершину, возвращает `None`.
- `pop()` удаляет и возвращает вершину.
- `peek()` возвращает вершину без удаления.
- `len(stack)` возвращает число элементов.
- `bool(stack)` возвращает `True`, если стек непустой.

`pop()` и `peek()` пустого стека вызывают `IndexError("Стек пуст")`.
Конструктор может принимать итерируемый объект и копирует его контейнер,
но не сами хранимые объекты.

### Генераторы

Каждый генератор принимает `size` и необязательный `seed`:

- `random_data`: случайные целые из диапазона `[-size, size]`.
- `sorted_data`: значения `random_data(size, seed)`, упорядоченные по возрастанию.
- `reversed_data`: те же значения по убыванию.
- `nearly_sorted_data`: отсортированный случайный набор после `max(1, size // 100)`
  случайных обменов разных позиций; при размере меньше двух обменов нет.
- `duplicates_data`: случайные значения из `{-2, -1, 0, 1, 2}`.

Размер должен быть неотрицательным `int`; отрицательное значение вызывает
`ValueError`, неверный тип (включая `bool`) - `TypeError`.
Seed должен быть `int` (без `bool`) или `None`, иначе `TypeError`.
Пустой размер возвращает новый пустой список.

Генераторы со случайностью используют локальный `random.Random(seed)` и не
изменяют глобальный генератор. Одинаковый seed воспроизводит набор в том же
окружении Python. Разные seed обычно дают разные случайные наборы, но это
не гарантия (например, пустые списки совпадают всегда). Seed влияет на содержимое
всех пяти типов наборов, в том числе отсортированного и обратного. При одинаковом
seed случайный, отсортированный, обратный и почти отсортированный наборы содержат
одинаковое мультимножество значений, что упрощает сравнение влияния порядка.

## Сложность

Ниже время указано в обычной модели, где сравнение, присваивание и арифметическая
операция над числом считаются O(1). Для произвольно больших Python-чисел время
сравнения и остатка от деления также зависит от числа бит. Память списков
считается в элементах/ссылках, без фиксированного числа байт на большое число.

- **Вставки:** лучший случай O(n), средний и худший O(n²). На обратном входе
  выполняется `n(n-1)/2` сдвигов. Дополнительная память публичной функции O(n)
  из-за копии входа; сам цикл вставок использует O(1) вспомогательной памяти.
  Проверка типов и копирование занимают O(n).
- **Слияние:** O(n log n) времени в лучшем, среднем и худшем случаях при n >= 2.
  Срезы и слияние требуют O(n) суммарной работы на каждом уровне.
  Пиковая дополнительная память O(n), включая результат и временные списки,
  плюс O(log n) кадров рекурсии. Общий объём создаваемых за всё выполнение
  списков O(n log n), но они не существуют одновременно.
- **НОД:** пусть `m = min(a, b)`. Количество шагов в худшем случае
  O(1 + log(m + 1)); при нулевом аргументе O(1). Итеративный вариант использует
  O(1) переменных, рекурсивный - O(1 + log(m + 1)) кадров стека. Размер самих
  больших целых в эту оценку памяти не включён.
- **Стек:** `push` и `pop` имеют амортизированное O(1) время. Отдельное
  изменение размера внутреннего списка может стоить O(n). `peek`, `len`
  и `bool` работают за O(1). Хранение n элементов требует O(n) памяти;
  создание из n элементов занимает O(n) времени и памяти.
- **Генераторы:** случайный и с дубликатами требуют O(n) времени; отсортированный,
  обратный и почти отсортированный - O(n log n) времени в худшем случае из-за
  предварительной сортировки. Для всех типов память O(n). У почти отсортированного
  набора после сортировки выполняется O(n/100) обменов. Подготовка данных не входит
  в измеряемое время benchmark.

## Методика benchmark

Полный запуск: 2 алгоритма × 5 типов × 3 размера × 5 повторов = 150 измерений.
В CSV 30 строк: одна строка на комбинацию алгоритма, типа входа и размера.

1. Генератор создаёт базовый набор до запуска таймера.
2. Эталонный результат вычисляется вне таймера.
3. Перед каждым повтором создаётся новая копия базового набора.
4. `time.perf_counter()` измеряет только полный вызов публичной сортировки.
5. После остановки таймера результат сравнивается с эталоном.
6. Записываются минимум, медиана и среднее в секундах, а также размер,
   количество повторов, seed, версия Python и платформа.

Оба алгоритма получают одинаковые значения для честного сравнения, но разные
объекты списков. Внутренняя проверка типов и копирование в самой сортировке
включены во время, поскольку являются частью её публичного контракта.
Генерация, внешняя подготовка копии, проверка результата и запись CSV не входят
в измерение. Повторы измеряют один фиксированный набор: это проверка времени
на выбранных данных, а не статистика по всем возможным входам.

Для сравнения используется медиана, менее чувствительная к одиночным задержкам.
Прогрев отдельно не выполняется; возможные накладные расходы первого вызова
также отражаются в измерениях. На малых размерах заметны накладные расходы
Python, на любых размерах - загрузка системы. В тестах нет порогов времени:
методика проверяется подставными часами, а правильность - ожидаемым результатом.

### Результаты выполненного запуска

Запуск выполнен на Python 3.14.8, macOS 26.4, ARM64, с `seed=42` и пятью
повторами. Ниже медианы в миллисекундах в порядке размеров 100, 1 000, 10 000:

- Случайный вход: вставки **0.088 / 9.094 / 977.289 мс**;
  слияние **0.084 / 1.065 / 13.202 мс**.
- Отсортированный: вставки **0.008 / 0.079 / 0.802 мс**;
  слияние **0.061 / 0.719 / 8.396 мс**.
- Обратный: вставки **0.169 / 18.076 / 1936.191 мс**;
  слияние **0.065 / 0.741 / 8.903 мс**.
- Почти отсортированный: вставки **0.012 / 0.338 / 27.376 мс**;
  слияние **0.067 / 0.813 / 10.405 мс**.
- С дубликатами: вставки **0.069 / 7.163 / 737.495 мс**;
  слияние **0.076 / 0.920 / 11.191 мс**.

На случайном входе увеличение размера с 1 000 до 10 000 замедлило вставки
примерно в 107.5 раза, а на обратном - в 107.1 раза. Это согласуется с
квадратичным ростом, для которого ожидается множитель около 100. На
отсортированном входе вставки замедлились в 10.2 раза, что соответствует O(n).

Слияние на этих пяти типах входа при том же росте размера замедлилось примерно
в 11.7-12.8 раза. Для n log n теоретическое отношение при 1 000 и 10 000
составляет около 13.3. Измерения согласуются с этой оценкой, но сами по себе
не доказывают асимптотику; доказательство опирается на устройство алгоритма.

Почти отсортированный набор заметно облегчает работу вставок относительно
случайного и обратного. Однако 1% обменов может перемещать элементы на большие
расстояния, поэтому число инверсий всё ещё может расти квадратично: такой
генератор не гарантирует линейное время вставок. Дубликаты также не устраняют
сдвиги элементов с меньшими значениями и не гарантируют линейного поведения.

На отсортированном входе вставки быстрее слияния: они делают один проход,
а слияние продолжает делить и собирать списки. На больших неупорядоченных
входах преимущество у слияния. Абсолютные значения времени зависят от среды
и будут отличаться при повторном запуске; полные значения находятся в CSV.

## Автоматические проверки

Тесты используют `unittest` из стандартной библиотеки:

- Для сортировок проверяются все обязательные граничные случаи, совпадение
  с эталоном на случайных массивах, сохранность исходного списка и ошибки типов.
- Слияние дополнительно проверяется на трёх базовых наборах из 10 000 элементов.
- НОД проверяется по известным примерам и по `math.gcd` на случайных парах.
- Для стека проверяются LIFO, `peek`, `len`, `bool`, ошибки пустого стека,
  независимость контейнера и инварианты при смешанных операциях.
- Для генераторов проверяются размеры, форма данных, seed, ошибки ввода
  и независимость от глобального состояния случайности.
- Для benchmark проверяются порядок событий относительно таймера, независимость
  копий, все комбинации запусков, CSV и обнаружение неправильной сортировки.

Все случайные тестовые наборы имеют фиксированные seed. Тест, временно меняющий
глобальный seed для проверки независимости, восстанавливает исходное состояние
в блоке `finally`. Тесты не требуют определённой скорости компьютера.

## Подготовка к защите

### 1. Почему сортировка слиянием имеет сложность O(n log n)?

На каждом шаге список делится примерно пополам, поэтому уровней рекурсии
O(log n). На каждом уровне суммарно обрабатывается O(n) элементов:
срезы копируют части списка, а слияние проходит по ним один раз.
Итого O(n log n). Рекуррентная запись для равных половин:
`T(n) = 2T(n/2) + O(n)`. Порядок входных элементов не меняет глубину деления.

### 2. Как добавить инвариант стека в виде теста?

Инвариант: после `push(x)` и следующего `pop()` возвращается `x`, а длина
и прежняя вершина восстанавливаются. Пример в `tests/test_structures.py`,
метод `test_push_pop_restores_stack`:

```python
stack = Stack([10, 20])
before = len(stack)
stack.push(30)
assert stack.pop() == 30
assert len(stack) == before
assert stack.peek() == 20
```

На защите можно самостоятельно добавить ещё один короткий тест: два вызова
`peek()` возвращают одну и ту же вершину и не меняют длину стека.

### 3. Почему нельзя измерять на одном изменяемом списке?

Если сортировка меняет список, после первого запуска он уже отсортирован.
Следующие повторы получают другой тип входа. Например, сортировка вставками
вместо квадратичного случая начинает работать за линейное время. Среднее таких
измерений вводит в заблуждение. Поэтому каждый запуск получает новую копию
исходных данных, причём копирование выполняется до таймера.

Наши функции не изменяют вход, но benchmark всё равно обеспечивает независимые
копии согласно заданию и остаётся корректным при замене алгоритма на изменяющий.
